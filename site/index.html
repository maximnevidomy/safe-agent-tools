The original idea

API Anything

From the tool library review: trust 60/100 · passed the library's security gate.
No flags in the library review. The risk below comes from the kind of tool, not from a finding in this repo.

The problem

A tool that fetches whatever URL the agent gives it can be tricked, by the agent or by text the agent read, into calling things on your own network: your laptop's admin pages, your cloud's secret-credentials address (169.254.169.254), internal services. This attack is called SSRF and it is one of the most common ways a fetch tool turns into a break-in.

CapabilityWhere we standAPI Anythingsafe-fetch
Reach any sitePartly thereReplays the site's own hidden requests learned in a browserReads any public page; extracts price, sale price, image
Sites with no public APIPartly thereCatalog of 114 pre-learned sitesStandard product data only (JSON-LD, OpenGraph, microdata)
Login and cookiesLeft out on purposeImports cookies from your browserNever uses cookies or sessions
Cache, request budget, change trackingAbout equalYesYes: 30 s cache, per-site budget, price change since last check
Errors an agent can act onAbout equalError class plus suggested next stepSame: class plus what to do next
Attack protection (private networks, redirects, DNS tricks)Ours is strongerNot describedEvery address checked, pinned connection, redirects re-checked

What we changed

  • Operates politely like the original: a short cache window, a per-site request budget and change tracking (what changed in price or name since your last check)
  • Every failure says its class and what to do next (blocked forever, retry later, use the official API)
  • Allowlist of hosts by default, https only (the live demo uses a public mode: any public website, still https and port 443 only, with every private range blocked)
  • Every address a name resolves to is checked; private and reserved ranges are refused
  • The connection is pinned to the address that was checked (no DNS trick between check and connect)
  • Every redirect is re-checked from scratch
  • Size cap, time cap, per-caller rate limiter

The original idea

Agent-Reach

From the tool library review: trust 70/100 · rejected at the security gate.
Library review: installed with curl; X, Reddit and Instagram work through account cookies, which risks bans and breaks terms of service.

The problem

Reading the web through a logged-in browser session means the agent holds your cookies, and scraping that way breaks the sites' rules and can get the account banned. Passing raw API answers or links straight to the agent also hands it private fields and dangerous links.

The original idea

From the tool library review: trust 30/100 · rejected at the security gate.

The problem

AI-built apps often ship with tables anyone can read or change, anonymous write access, policies that say 'true', functions that run with elevated rights, or a master key pasted in the code. A checklist that only greps for leaked keys misses most of this.

The original idea

FreeLLMAPI · also OmniRoute

From the tool library review: trust 60/100 · new (OmniRoute: trust 30).
Library review: code and data go to free providers, some of which train on it. OmniRoute: routes code to 200+ unknown free providers, leak risk.

The problem

A router that sends every prompt to whichever free provider answers also sends your private data there: client notes, emails, API keys pasted by accident. Free providers may store or train on it, and the router's own logs can become a second leak.

The original idea

CLI-Anything

From the tool library review: trust 75/100 · passed the library's security gate.
No flags in the library review. The risk below comes from the kind of tool, not from a finding in this repo.

The problem

Running a command built from text the agent wrote is the classic injection hole: one stray '&&' or ';' and the agent's text becomes a second command. The child process also inherits every secret in your environment, and a runaway command can print forever or never stop.

CLI-Anything vs safe-exec

CapabilityWhere we standCLI-Anythingsafe-exec
Make any software usable by an agentNot builtGenerates a CLI for GIMP, Blender, LibreOffice and moreYou list the programs you trust, one by one
Structured JSON outputAbout equalYes (--json)Always one JSON shape with error class and next step
Agent can discover what existsPartly thereSKILL.md and a hubdescribePolicy() lists names and usage
Shell tricks and secretsOurs is strongerRuns real backendsNo shell, scrubbed environment, timeout and output cap

What we changed

  • Agents get one stable JSON answer for every call, success or failure, with an error class and a next step, and can read the allowlist (names, usage) before calling
  • Commands are chosen by name from an allowlist and mapped to absolute paths
  • No shell, so special characters are just text
  • Argument count, length and per-command rules
  • The child gets a clean environment
  • Hard timeout and output cap

From the tool library review: trust 50/100 · passed the library's security gate.

The problem

A simple 'approved: true' flag is not enough. The text can be changed after approval, one approval can be reused, an old approval can be used days later, and an unsigned token can be written by the agent itself.
